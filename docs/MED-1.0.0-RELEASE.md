## Изменения

- `EmojiPicker.csproj`: сборка/EXE MED, версия 1.0.0, полное имя Mikhalych Emoji Dock,
  стандартные SDK-метаданные, обновлённые pack URI ресурсов. Namespace и путь проекта прежние.
- `App.xaml.cs`: скрытый по умолчанию NotifyIcon, доступ к настройкам и выходу,
  явный `--background`, `--settings` и адресованный текущему пути `--shutdown`.
  Старый mutex сохранён для защиты от параллельного запуска Classic Emoji Picker.
  Повторный фоновой старт не открывает панель; ручной повторный запуск открывает её.
  Выход сохраняет существующие отмену вставки, восстановление буфера и Dispose hook.
- `AppDataPaths.cs`, `Settings.cs`, `Logger.cs`, история в `MainWindow.xaml.cs`:
  единый каталог данных, безопасная миграция, атомарная запись с `.bak`.
  Повреждённые настройки/история не заменяются пустыми значениями; показывается предупреждение.
- `SettingsWindow.xaml(.cs)` и шестерёнка в панели: видимость значка, автозапуск,
  диагностика, точный путь данных и «Выход из MED». Размер панели/сетка прежние;
  поле поиска немного сужено для размещения кнопки. Тёмная/светлая тема сохранены.
- `StartupRegistration.cs`: только значение MED в HKCU Run, кавычки вокруг пути,
  `--background`; обнаружение другого/перемещённого пути, явное исправление и удаление.
- `installer/EmojiPicker.iss`: отдельный постоянный AppId MED, per-user,
  `%LOCALAPPDATA%\Programs\MED`, без обязательного UAC, ярлыки меню «Пуск»,
  без ярлыка рабочего стола и без runtime-установщиков. Автозапуск выбран по умолчанию;
  на обновлении учитывается ранее отключённый автозапуск. Удаление сохраняет данные
  и убирает только принадлежащую этой установке команду HKCU Run.
  Принудительный taskkill удалён; используется корректный `MED.exe --shutdown`.
- `tools/Build-MEDRelease.ps1`, `build.bat`: проверки, self-contained публикация,
  ZIP из явного списка payload, вызов только существующего ISCC, отчёт и SHA-256.
  Старый per-machine MSI оставлен как исторический исходник, исключён из MED-сборки.
  GitHub workflow теперь только ручная подготовка артефактов без публикации релиза,
  удаления релизов или установки инструментов. Workflow не запускался.

Сторонние NuGet-пакеты не обновлялись. Параметры пользовательской публикации:
`PublishTrimmed=false`, `PublishSingleFile=false`, `PublishReadyToRun=false`,
`DebugType=None`, `DebugSymbols=false`. PDB исключены; штатное ZIP-сжатие уменьшает

## Каталоги и миграция

Установленная версия: `%APPDATA%\MED`. Portable определяется наличием
`portable.txt` рядом с EXE: данные в `Data`, автозагрузка автоматически не включается.
При первом запуске копируются отсутствующие `settings.json`, `recent.json`,
`debug.enabled` из `%APPDATA%\ClassicEmojiPicker`; оригиналы не удаляются.
Существующие файлы MED не перезаписываются миграцией. Старые диагностические
журналы остаются в исходном каталоге, новые записываются в выбранный каталог MED.

Недоступный для записи portable Data вызывает явный переход в отдельный каталог
`%APPDATA%\MED\Portable\<идентификатор-пути>`. Он остаётся основным до явного переноса:
иначе возвращение прав записи могло бы восстановить устаревшую локальную историю.
В предупреждении и настройках указан точный путь. Порядок переноса/возврата к Data
описан в пользовательской инструкции. Если недоступны и Data, и резервный каталог,
MED останавливает запуск с объяснением, не удаляя существующие данные.

Старый ClassicEmojiPicker Run не меняется. Перед переходом отключи его автозапуск
в старом приложении и заверши старую копию, чтобы она не перехватила mutex после входа.
Перенос portable не может исправить Run самостоятельно, пока новая копия не запущена:
для этого есть понятные действия «включить заново» и «удалить запись» в настройках.

## Что не проверено и ограничения

На компьютере продолжает работать старая копия из `publish/med52-win-x64`.
Она не останавливалась. Новая пользовательская MED.exe с реальным глобальным hook
не запускалась параллельно с ней; проверялся изолированный жизненный цикл App.
Реальные Win + ., ввод, буфер, прокрутка, DPI и визуальные настройки требуют
ручной проверки нового portable после выхода из старого приложения.

Реальные установка, обновление, удаление, запись Run и вход/перезагрузка Windows
не выполнялись. Setup EXE и его размер отсутствуют, поскольку нет компилятора.
До этой проверки выпуск двух полностью готовых вариантов не завершён.
Предупреждение при экстремально быстрых вставках и ограничения повышенных окон
сохранены. У внешнего приложения собственная поддержка Unicode/шрифтов.
При предупреждении скрытый значок временно появляется для Shell-уведомления,
после закрытия уведомления/таймера снова скрывается; настройка не меняется.
Цифровой подписи нет.

## Первый запуск и дальнейшая ручная проверка

Полная инструкция включена в ZIP: `README-MED.txt`, исходник
`docs/MED-1.0.0-README.txt`.

1. Закрой старую копию через меню выхода; распакуй ZIP в доступный для записи каталог.
2. Запусти MED.exe; убедись, что панель и постоянный значок не появляются.
3. Win + . → поиск на русском/английском, Fluent/fallback, повторная и ZWJ-вставка,
   история; Esc и внешний клик должны закрывать только панель.
4. Шестерёнка → включить/выключить значок; перезапустить и проверить сохранение.
   «Выход из MED» должен вернуть штатную панель Windows. Настройки можно открыть
   также командой MED.exe --settings.
5. После отдельного разрешения на изменение реальной автозагрузки проверить
   включение/отключение и перенос пути. Этот этап подготовки сам Run не изменяет.
6. После предоставления ISCC пересобрать через tools/Build-MEDRelease.ps1,
   затем отдельно разрешить/проверить установку, повторную установку и удаление.
