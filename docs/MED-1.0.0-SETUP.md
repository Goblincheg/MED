## Архитектура, права, автозапуск

- Реальный PE-заголовок Setup: **AMD64 / 0x8664**, PE32+.
- Реальный XML-манифест Setup: **requestedExecutionLevel=asInvoker**.
- `PrivilegesRequired=lowest`; разрешение переключения в all-users/admin не задано.
- Каталог по умолчанию: `%LOCALAPPDATA%\Programs\MED`, текущий пользователь.
- AppId MED сохранён: `{64F54C6E-208D-4A1C-B37E-04A748DCE153}`; обновление использует
  тот же идентификатор. Реальное обновление пока не выполнялось.
- Свежая установка: задача startup выбрана по умолчанию, её можно отключить.
  На обновлении предусмотрено сохранение ранее отключённой автозагрузки.
- Запись только в HKCU Run, имя MED, команда `"<каталог>\MED.exe" --background`.
- Два ярлыка в меню «Пуск»: MED и MED — настройки. Записей desktop нет.
- При снятии задачи startup и при деинсталляции вызывается RemoveOwnedStartup.
  Она удаляет MED Run только при точном совпадении с командой этой установки,
  без учёта регистра. Автозагрузка другой portable-копии не удаляется.
- Пользовательские настройки/история вне каталога установки сохраняются;
  UninstallDelete отсутствует. Для выхода используется адресованный --shutdown,
  принудительного taskkill нет.

Эти условия проверены по исходнику и успешной компиляции Pascal-кода. Проверка
UAC дополнительно выполнена чтением PE-ресурсов, без запуска Setup. Поведение
реальной установки/деинсталляции и HKCU Run нужно проверить вручную.
Цифровой подписи у Setup нет; SmartScreen — отдельный от UAC механизм.

## Ручная проверка

Заверши работающую portable-копию через «Выход из MED», затем запусти Setup.
Проверь выбранную по умолчанию автозагрузку и возможность её снять, отсутствие
обязательного UAC/ярлыка desktop, ярлыки меню «Пуск» и скрытый фоновый старт.
После входа в Windows проверь Win + ., поиск, вставку, настройки и историю.
Затем отдельно проверь повторную установку и удаление: Run этой установки должен
исчезнуть, `%APPDATA%\MED` — остаться. Известное предупреждение при экстремально
быстрой вставке сохранено; его исправление в этап 6.1 не входило.
